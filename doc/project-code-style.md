## 代码规范约束

### 必须

- 必须保持最小可读变更，优先修复后复用现有抽象，不引入新层次替代既有职责。
- 必须使用明确的错误边界：同步/异步执行必须有错误捕获、日志记录与错误语义返回。
- 必须保持配置化优先：端口、外部服务地址、超时、凭证路径采用环境变量或现有配置入口，不得散落常量化。
- 必须保证新代码可测试性，不要求覆盖率口径，但应便于替换依赖与单元验证。
- 必须保持日志可追溯，涉及设备标识、Token、凭证的输出需脱敏。
- 禁止在未确认的前提下修改跨模块公共接口，禁止同时改动超过一个核心责任域而无分阶段说明。

### 禁止

- 禁止在文档中定义临时实现细节并将其作为代码真相来源。
- 禁止在 `test` 之外提交调试脚本、命令快照、临时 mock 数据作为生产代码。
- 禁止在无必要时引入与业务无关的新依赖。
- 禁止默认主动新增测试框架、构建脚本和发布链路配置。
