# Mobile Matrix 单设备控制页右侧工作区设计

## 背景

当前 `/control/:serial` 已形成“左侧设备主舞台 + 右侧工具区”的基本结构，但右侧仍以七个同级标签和平铺工具卡组织内容。该结构无法清楚表达 Mobile Matrix 后续群控方向，也会让日志、截图、文件管理等不同性质的工具争夺同一层级。

本设计只整理右侧信息架构和视觉布局。Airtest 执行服务、脚本配置、任务运行、批量画面同步与执行结果均不在本期范围内。

## 已确认决策

- 右侧默认进入“群控执行”，现有 STF 功能统一收进“设备工具”。
- “群控执行”采用三步向导：选择设备、配置操作、确认执行。
- 进入控制页时，左侧当前设备自动成为第一个目标设备。
- Airtest 未接入时采用真实边界空状态：只开放第一步，第二步和第三步明确禁用，不提供伪执行按钮或计时状态。
- 顶部使用“群控执行 / 设备工具”双入口切换，不使用覆盖工作台的抽屉。
- “设备工具”采用分类侧栏和单一内容区，不使用工具卡首页或七个横向标签。

## 页面结构

### 左侧设备主舞台

左侧保持现有设备名称、控制按钮、实时屏幕和 Android 导航能力，不改变 `ControlService`、minicap、minitouch、租约或屏幕事件。

### 右侧工作区顶栏

右侧顶栏包含工作区标题和两个同级模式入口：

1. “群控执行”为默认激活项。
2. “设备工具”切换到现有 STF 工具集合。

模式切换只改变右侧内容，不重建左侧屏幕、不释放设备、不修改当前控制会话，也不持久化到浏览器存储。

### 群控执行

群控执行区使用固定三步结构：

1. **选择设备**：显示当前控制设备的名称、serial 摘要与真实连接状态。当前设备由控制页已有 `$scope.device` 提供并自动选中。
2. **配置操作**：本期禁用，并使用文字说明需要后续 Airtest change 才能开放。
3. **确认执行**：本期禁用，不显示可运行的主按钮、虚构参数或模拟进度。

第一步下方展示真实边界空状态，明确说明“Airtest 执行引擎尚未接入”。本期不读取第二套设备列表、不新增目标选择 API，也不保存目标集合；未来 Airtest change 可以在该边界内替换空状态，而无需再次调整工作区导航。

### 设备工具

设备工具采用左侧分类导航和右侧单一内容区，复用现有模板与事件：

- **常用操作**：Dashboard；其内部继续承载 Navigation、Clipboard、App Upload、Shell、Apps 和 Remote Debug。
- **记录诊断**：Logs、Screenshots。
- **设备管理**：Automation、File Explorer、Advanced、Info。

每次只挂载当前选中的工具模板。切换工具不复制模板、不改变业务事件，也不把现有工具迁移到新的后端服务。

## 状态与数据边界

- `workspaceMode` 仅允许 `execution` 与 `tools`，默认值为 `execution`。
- `executionStep` 本期固定为第一步；后两步以禁用语义呈现。
- 当前目标设备直接引用控制页已有设备对象，不复制 STF 状态，不建立新的群控状态仓库。
- 设备离线时沿用现有 `FatalMessage` 处理；工作区本身不重试连接、不伪造在线状态。
- 工具激活状态只存在当前控制页内存中，离开页面后不持久化。

## 响应式与视觉规范

- 宽桌面保持左侧 360–480px 设备主舞台，右侧占用剩余空间。
- 右侧较窄时，模式入口保持可横向容纳；设备工具分类侧栏折叠为顶部可滚动工具导航，内容区保持单列。
- 所有操作触达高度不少于 44px，并提供键盘焦点、激活文字和图标，状态不得只依赖颜色表达。
- 功能图标继续使用本地 Material Design Icons Round。
- 页面只使用现有 `--mm-*` 语义 token，支持 `default` 液态玻璃蓝和 `roseGlow` 玫瑰流光，不新增硬编码颜色、第三套主题或页面副本。

## 错误与安全

- Airtest 不可用不是运行错误，而是明确的能力未接入状态；界面不得显示失败日志或模拟执行结果。
- 当前设备不可用时继续由 STF 实时状态和既有离线弹窗反馈，工作区不降级为假设备。
- 页面不得展示或记录 Token、ADB key、完整远程地址或执行凭据。

## 实现边界

预计只调整控制页 controller、Pug 模板和控制页作用域样式，并按需要新增一个控制页内部模板。不得修改 STF Provider、设备协议、租约 API、根启动脚本或主题 token 文件。

## 验收

1. 打开可控制设备时，右侧默认显示群控执行第一步，当前设备真实名称与状态可见。
2. 配置操作和确认执行明确禁用，并说明 Airtest 尚未接入；页面不存在可产生伪结果的执行按钮。
3. 切换到设备工具后，三组分类和七个现有工具可访问，每次只显示一个工具内容。
4. 工具切换、模式切换不影响左侧实时屏幕和控制会话。
5. 两套主题、宽桌面和紧凑视口均无横向溢出，焦点、文字和边界可读。
6. 构建和静态检查通过；真实 Airtest 执行不属于本期验收项。

## 回退

若新工作区影响现有工具或控制会话，可恢复当前单一 `nice-tabs` 工具区；所有现有模板、controller 事件和 STF 控制协议保持原状，因此不涉及数据迁移。
