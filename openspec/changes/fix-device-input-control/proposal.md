# 修复桌面控制台的真机输入、剪贴板与滑动

## 变更原因

当前 Flutter 桌面控制台能够识别 Android 真机，但电脑键盘输入依赖 `ACTION_SET_TEXT` 广播。该广播只有在 STF 输入法处于激活状态时才可靠，搜狗、百度等第三方输入法下会静默丢失。此前剪贴板降级又误用了 STF Service 并未注册的 `ACTION_SET_CLIPBOARD` 广播，广播即使返回 `result=0` 也没有真正写入剪贴板；触摸移动只在抬手时补发一次，导致滚动和拖动体验不稳定。

## 目标范围

- 点击真机画布后，电脑物理键盘和桌面输入法产生的中文、英文、标点、Emoji 能可靠进入当前手机焦点输入框。
- Cmd+V（macOS）或 Ctrl+V（Windows/Linux）读取电脑剪贴板，按 STF 复合通道写入手机剪贴板并触发 Android 原生粘贴。
- 真机主舞台不显示额外输入栏；只有用户点击手机画面后，隐藏输入代理才接管桌面键盘和输入法提交，交互与 Web STF 保持一致。
- 修复 ADB 文本/按键命令的串行时序，并把点击、长按、滑动切换到与 Web 完全一致的 STF Socket.IO 设备通道，避免触控因 ADB 命令往返而延迟。
- 保持现有桌面 Flutter 主机控制 Android 真机的边界，不引入 iOS/WDA；仅增加经过验证的 Dart Socket.IO 客户端依赖，不改 STF 服务端。

## 非目标

- 不重构 STF、屏幕流协议或设备发现模型。
- 不修改 STF 服务端、protobuf 或 minitouch 实现。
- 不把 `ACTION_SET_TEXT` 作为跨输入法文本注入的主路径。
- 不实现任意代码执行、远程剪贴板监听或新的设备权限提升。
- 不修改测试、发布配置或用户已有的无关工作区改动。
- 不在手机画面之外自动抢占桌面键盘焦点，也不显示同步输入提示、图标或占位区域。

## 回退方式

若设备不支持 KEYCODE_PASTE，控制台仍保留原有物理按键通道；输入失败不会阻塞页面。触控连接失败时由 Socket.IO 重连并重新解析动态设备 channel，不回退到延迟的 ADB 合成滑动。后续可在独立变更中接入 STF Agent 的 `clipboard.paste` 协议，不在本次扩大范围。
