# 修复桌面控制台的真机输入、剪贴板与滑动

## 变更原因

当前 Flutter 桌面控制台能够识别 Android 真机，但电脑键盘输入依赖 `ACTION_SET_TEXT` 广播。该广播只有在 STF 输入法处于激活状态时才可靠，搜狗、百度等第三方输入法下会静默丢失。现有剪贴板实现也未等待设备剪贴板写入完成就发送粘贴事件，ADB 会话未就绪时还可能丢失第一批命令；触摸移动只在抬手时补发一次，导致滚动和拖动体验不稳定。

## 目标范围

- 点击真机画布后，电脑物理键盘和桌面输入法产生的中文、英文、标点、Emoji 能可靠进入当前手机焦点输入框。
- Cmd+V（macOS）或 Ctrl+V（Windows/Linux）读取电脑剪贴板，按 STF 复合通道写入手机剪贴板并触发 Android 原生粘贴。
- 真机主舞台不显示额外输入栏；只有用户点击手机画面后，隐藏输入代理才接管桌面键盘和输入法提交，交互与 Web STF 保持一致。
- 修复 ADB 交互命令的串行时序，使点击、长按、滑动、按键和刷新请求不因会话启动竞态而丢失。
- 保持现有桌面 Flutter 主机控制 Android 真机的边界，不引入 iOS/WDA 或新的外部依赖。

## 非目标

- 不重构 STF、屏幕流协议或设备发现模型。
- 不把 `ACTION_SET_TEXT` 作为跨输入法文本注入的主路径。
- 不实现任意代码执行、远程剪贴板监听或新的设备权限提升。
- 不修改测试、发布配置或用户已有的无关工作区改动。
- 不在手机画面之外自动抢占桌面键盘焦点，也不显示同步输入提示、图标或占位区域。

## 回退方式

若设备不支持 KEYCODE_PASTE，控制台仍保留原有物理按键和手势通道；输入失败不会阻塞页面。后续可在独立变更中接入 STF Agent 的 `clipboard.paste` 协议，不在本次扩大范围。
