## Purpose

为 Mobile Matrix 的本机或可信内网控制台提供可验证的 Android Airtest 执行闭环，使操作者能选择一个或多个可用设备、选择项目内受限任务并安全执行和查看逐设备真实结果。

## ADDED Requirements

### Requirement: 执行引擎状态可见
系统 SHALL 向控制台提供 Airtest 执行引擎的就绪状态。状态必须明确区分运行时不可用、设备不可执行和可执行，不得将静态界面状态表示为已连接。

#### Scenario: 本机运行时可用
- **WHEN** 已配置的 Airtest Python 可以加载 Airtest 且当前设备在 STF 中可用
- **THEN** 控制台显示执行引擎已就绪，并允许进入动作配置步骤

#### Scenario: 本机运行时不可用
- **WHEN** Airtest Python 缺失、无法启动或无法加载 Airtest
- **THEN** 控制台显示不可用原因，并禁止提交执行请求

### Requirement: 多台已选设备的受限 Airtest 动作可执行
系统 SHALL 允许操作者从 STF 当前已连接的设备中选择一个或多个处于 `available` 或当前控制会话 `using` 状态的 Android 设备执行预定义动作；系统 MUST 禁止选择 `busy`、`offline`、`unauthorized`、`preparing` 或 `automation` 状态设备，并拒绝任意脚本、任意命令或不支持的动作输入。每台设备的执行结果必须包括目标设备、动作、成功或失败状态以及可用于诊断的结果信息。

#### Scenario: 成功采集多台设备画面
- **WHEN** 操作者选择一台或多台可用设备并提交“采集屏幕”动作
- **THEN** 系统通过 Airtest 分别连接每台设备，并返回每台设备真实的标识与屏幕分辨率结果

#### Scenario: 部分设备执行失败
- **WHEN** 多台目标设备中部分设备在执行时已不可连接
- **THEN** 系统保留其他设备的真实结果，并明确标识失败设备及其原因

#### Scenario: 设备已离线
- **WHEN** 操作者提交动作时目标设备不再可连接
- **THEN** 系统返回设备不可执行错误，且不得报告执行成功

#### Scenario: 不支持的动作
- **WHEN** 客户端提交不在预定义动作集合内的动作
- **THEN** 系统拒绝该请求并返回明确的校验错误，且不得在设备上执行命令

### Requirement: 执行工作台与真实状态联动
系统 SHALL 让执行工作台依次呈现可选设备、多选状态、配置动作和逐设备运行结果。只有在执行引擎已就绪且至少选中一台可执行设备时，动作配置与执行控件才可用；执行期间必须展示进行中状态，完成后必须展示该次请求的逐设备真实成功或失败结果。

#### Scenario: 引擎已就绪并完成动作
- **WHEN** 至少一台已选设备可执行（包括当前控制会话中的 `using` 状态）且动作返回
- **THEN** 工作台将配置和运行步骤标记为完成，并展示每台目标设备及执行结果

#### Scenario: 执行失败
- **WHEN** Airtest 返回执行错误或请求失败
- **THEN** 工作台保留所选动作并展示失败原因，以便操作者修正后重试

### Requirement: 任务脚本可选择且执行可重复
系统 SHALL 从项目内登记的任务目录提供脚本选择项，客户端只能提交登记的任务标识，不得提交任意本地路径或脚本内容。一次执行完成或失败后，工作台 MUST 清除运行中状态并允许再次执行；每台设备的结果 MUST 包含本次执行生成的真实截屏地址（若任务成功完成截图步骤）。

#### Scenario: 选择抖音任务
- **WHEN** 操作者打开执行工作台
- **THEN** 工作台展示已登记的抖音 Airtest 任务，并可将其作为当前执行任务

#### Scenario: 执行完成后再次运行
- **WHEN** 一次任务成功或失败返回
- **THEN** 工作台保留结果供查看，同时恢复任务选择和运行按钮，操作者可以再次提交

#### Scenario: 查看真实执行截图
- **WHEN** 某台设备的任务生成了截图
- **THEN** 该设备结果展示可打开的截图，并且截图来自本次任务而不是静态占位图
